# VESPER 7.1 — планировщик личной вселенной

Новая модель задач и интерфейс на замену последовательным патчам VESPER 3–6. Статические файлы находятся в `public/`, серверные функции — в `api/`. Прежняя версия остаётся в истории Git.

## Что реализовано

- Цели, самостоятельные дела, ежедневные повторы, будни и выбранные дни недели.
- Длительность, таймер с паузой, ручной учёт фактического времени.
- Отдельные выполнения, пропуски, отмена одного выполнения и перенос с историей.
- Поиск свободного времени по длительности, срочности, доступным часам, занятости и крайнему сроку.
- Результаты ДЗ: меньше 70% создаёт задачу повторения, новая успешная попытка закрывает исправление.
- XP и звёздная пыль без повторной награды за одну галочку.
- Космическая карта, анимированный Кайро и серверный ИИ-чат.
- Дневник цикла, симптомы, отметки половых актов, фактические периоды и ориентировочные прогнозы.
- Лента NASA, экспорт/импорт и перенос `vesper3` с сохранением исходной копии.
- Вход по почте, подтверждение адреса, восстановление пароля и синхронизация через существующий Firebase `vesper-21ef9`.
- Очередь изменений сохраняется до подтверждения облака; данные и очередь разделены по аккаунтам.
- Подготовлены Web Push и отправитель напоминаний.

Публичная конфигурация Firebase уже включена. Владелец должен включить Authentication и опубликовать правила Firestore в Firebase Console: [пошаговая инструкция](docs/FIREBASE_SETUP.md). Для базового входа и синхронизации серверные секреты не нужны. ИИ и фоновые уведомления требуют отдельных настроек; без них интерфейс сообщает, что службы ещё не подключены.

## Запуск и проверки

Нужен Node.js 22 или новее.

```sh
npm ci
npm run dev
```

Открой `http://localhost:4173`. В первом окне можно создать пустой локальный профиль или явно выбрать пример. Для локальной конфигурации скопируй `.env.example` в `.env.local`; этот файл игнорируется Git.

```sh
npm run check
npm test
npm run test:browser
npm run test:firebase
npm run build
```

Браузерные проверки используют Chromium, по умолчанию `/usr/bin/chromium`; другой путь задаётся через `CHROMIUM_PATH`. Если системного браузера нет, выполни `npx playwright install chromium`.

Проверки Firebase требуют Java 21 и запускают только локальные эмуляторы Authentication и Firestore с виртуальным ID `demo-vesper-sync`. Облачный проект не создаётся и не изменяется. Проверяются подтверждение почты, обмен между двумя независимыми сеансами, смена аккаунта и запрет доступа к чужим данным. Эмуляторы не заменяют проверку настроек настоящего проекта и получения push на телефоне.

## Бесплатный профиль и синхронизация

Используется уже созданный проект **`vesper-21ef9`**, план **Spark**. Новый проект не нужен. Точная последовательность действий в Firebase Console и Vercel приведена в [инструкции подключения](docs/FIREBASE_SETUP.md).

Публичный Web config находится в [server/firebase-config.js](server/firebase-config.js). Переменная `FIREBASE_WEB_CONFIG` нужна только для явного переопределения конфигурации того же проекта. Конфигурация другого проекта отклоняется.

Локальный профиль можно использовать отдельно. После входа его записи не загружаются автоматически; перенос выполняется через Профиль → «Перенести их в этот профиль» с подтверждением замены.

У писем подтверждения, восстановления и входа по ссылке разные квоты: [Firebase Auth Limits](https://firebase.google.com/docs/auth/limits). Основной сценарий использует почту и пароль.

## Бесплатный ИИ Кайро

1. На [Cloudflare Workers AI](https://dash.cloudflare.com/) включи **Workers Free** и создай токен доступа к Workers AI для своего аккаунта.
2. В Vercel добавь `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_AI_TOKEN`. Модель по умолчанию — `@cf/qwen/qwen3-30b-a3b-fp8`; другая задаётся в `CLOUDFLARE_AI_MODEL`.
   Для серверной проверки пользователя и квот также нужен `FIREBASE_SERVICE_ACCOUNT` из проекта `vesper-21ef9`. Закрытый JSON хранится только в Vercel Environment Variables.
3. После Redeploy проверь `/api/config`: `chat` должен быть `true`, затем отправь настоящий запрос из подтверждённого профиля.

Чат ограничен 30 запросами на пользователя в сутки и общей бесплатной квотой провайдера. При исчерпании возвращает понятную ошибку. Платный тариф автоматически не подключается. Модель получает ограниченный контекст задач; дневник цикла и отметки половых актов автоматически не передаются.

## Уведомления при закрытом сайте

1. Сгенерируй VAPID-ключи через пакет `web-push` и длинный случайный `CRON_SECRET`.
2. Сохрани в Vercel `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (контакт `mailto:`) и `CRON_SECRET`.
   Для серверной отправки также нужен `FIREBASE_SERVICE_ACCOUNT` из проекта `vesper-21ef9`.
3. Создай Worker из папки [cloudflare](cloudflare). Задай в его настройках `SITE_URL` и тот же `CRON_SECRET`. Конфигурация запускает отправитель раз в минуту на Workers Free.
4. В VESPER открой Профиль → «Включить на этом устройстве» и разреши уведомления. Повтори для каждого нужного устройства.
5. Создай задачу с близким напоминанием, закрой сайт и проверь доставку, затем перенос и отмену.

Vercel Hobby Cron не используется как поминутный планировщик. На iPhone/iPad Web Push требует установки сайта на домашний экран и поддерживаемой версии ОС. Доставка зависит от разрешений, сети и платформы.

## Сохранение данных

- Перед миграцией создаётся `vesper3:backup-before-v7`; исходный `vesper3` не изменяется.
- Цели, этапы и отдельные задачи становятся общей моделью; старые начисления не добавляются повторно.
- Убранные чтение, привычки и прочие поля сохраняются в исходной копии `legacy` для экспорта.
- Локальные записи не переносятся в облачный профиль автоматически: есть отдельное действие с подтверждением замены.
- Firestore изолирует записи по подтверждённому UID. Правила нужно проверить на реальном проекте до выдачи друзьям.
- Перед платным магазином понадобится серверная проверка экономики. Игровой клиентский баланс не предназначен для реальных покупок.

## Дневник цикла

Факты отделены от календарных предположений. Новые начала изменяют историю и ориентировочный диапазон. При короткой/нерегулярной истории фертильное окно не показывается. Прогноз не подтверждает овуляцию, не вычисляет индивидуальную вероятность беременности и не используется для выбора контрацепции. Медицинские источники доступны в интерфейсе.

## Публикация

Ветка разработки предназначена для Vercel Preview. После проверки интерфейса и облачных функций изменения можно объединить с `main`; существующий проект использует `vercel.json` и каталог `public/`.
