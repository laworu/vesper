# Устройство VESPER 7

- `public/src/domain.js`: правила задач, выполнений, повторений, прогресса, наград, планирования, ДЗ, календарных оценок и миграции.
- `public/src/store.js`: раздельные локальные профили и обмен отдельными сущностями с облаком.
- `public/src/sync.js`: сохранённая на устройстве очередь изменений, подтверждения записи и объединение снимков.
- `public/src/cloud.js`: Firebase Web SDK, авторизация, синхронизация, подписка Web Push и серверные запросы.
- `public/src/views.js`: представления с экранированием пользовательского текста.
- `public/src/app.js`: формы, навигация, таймер, подтверждения удаления и импорта.
- `api/`: публичная конфигурация без серверных секретов, ИИ, новости, push-подписки и защищённая отправка.
- `server/core.js`: серверные проверки пользователя, запросов и квот.
- `server/http.js`: обработка HTTP и ошибок без Firebase Admin. Публичная конфигурация входа не загружает SDK серверных служб.
- `public/sw.js`: оболочка и получение уведомлений при закрытом сайте.
- `firestore.rules`: изоляция владельцев, закрытые служебные коллекции.
- `cloudflare/`: поминутный запуск отправки.

## Выполнения и награды

У задачи есть расписание, у выполнения — стабильный ID `taskId@originalDate`. Перенос сохраняет ID. Награда вычисляется по одному завершённому выполнению; отмена и повторная отметка не создают второй доход.

План создаётся ограниченным горизонтом. Изменение расписания не переписывает завершённые и явно перенесённые выполнения. Цель завершается явно, а не после одного удачного дня регулярных дел.

## Синхронизация

Отдельные документы целей, задач, попыток и выполнений не перезаписывают весь профиль одним документом. Удаления передаются отметками. При одновременном редактировании одной сущности действует порядок записей Firestore: последняя принятая сервером запись заменяет документ целиком. Время на часах устройства не определяет победителя; совместное редактирование полей не реализовано.

Пустой первый снимок из кэша не считается пустым облачным профилем. Отправка очереди начинается после снимка сервера. Подтверждение удаляет только отправленную версию изменения: новые правки, сделанные во время запроса, остаются в очереди. Очередь сохраняется вместе с локальной копией состояния под ключом конкретного UID. Смена аккаунта останавливает подписку и запрещает продолжать его старые запросы от имени нового пользователя.

Web config проекта `vesper-21ef9` является публичным. Firebase Admin используется только серверными службами ИИ и push; базовая синхронизация обращается к Firestore от имени подтверждённого пользователя и проверяется Security Rules. Analytics не инициализируется.

Защита от повторной галочки не равна защите от владельца, вручную меняющего собственные записи. Серверная экономика нужна перед реальными покупками.

## До первого выпуска друзьям

1. Проверить изоляцию двух реальных аккаунтов правилами Firestore.
2. Проверить запись, изменение, удаление, время и состояние Кайро с двух устройств.
3. Проверить реальный русский ИИ-ответ и поведение при лимите.
4. Проверить push при закрытом окне и после установки на iPhone, перенос и отмену.
5. Импортировать реальную копию старой версии и сохранить исходный JSON.

Автоматические проверки используют локальные эмуляторы Firebase. Включение провайдеров, разрешённые домены и публикация правил настоящего проекта выполняются владельцем по [инструкции](FIREBASE_SETUP.md). Успешная проверка на эмуляторах не означает, что настройки Firebase Console уже изменены.
