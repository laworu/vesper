# Подключение существующего Firebase к VESPER

Проект: **`vesper-21ef9`**, веб-приложение **VESPER**, бесплатный план **Spark**. Публичный `firebaseConfig` уже включён в код. Создавать другой проект, регистрировать ещё одно приложение или включать платный план не требуется.

## 1. Включить вход

Открой [Authentication проекта vesper-21ef9](https://console.firebase.google.com/project/vesper-21ef9/authentication).

1. Нажми **Get started / Начать**, если сервис ещё не включён.
2. Открой **Sign-in method / Способы входа** → **Email/Password / Электронная почта и пароль**.
3. Включи первый переключатель **Email/Password** и нажми **Save / Сохранить**. Вход по ссылке без пароля для этого сценария не нужен.
4. При желании включи **Google** и выбери контактный адрес поддержки. Основной сценарий работает через почту и пароль.

В приложении есть регистрация, отправка письма подтверждения, повторная отправка, кнопка «Я подтвердил(а) почту» и восстановление пароля. Доступ к облачным записям открывается после подтверждения почты.

## 2. Добавить домены сайта

В Authentication открой **Settings / Настройки** → **Authorized domains / Разрешённые домены** и добавь:

```text
vesper-xi-flame.vercel.app
vesper-git-codex-vesper-v7-planner-laworu.vercel.app
```

Вводи только имя домена, без `https://` и пути. `vesper-21ef9.firebaseapp.com` оставь в списке. Если подключишь собственный домен, добавь и его. Для проверки локального сайта можно отдельно добавить `localhost`; в новых проектах он может отсутствовать по умолчанию.

Preview может требовать входа в твой аккаунт Vercel. Это отдельная защита Vercel, она не заменяет вход в VESPER.

## 3. Включить Firestore

Открой [Cloud Firestore проекта vesper-21ef9](https://console.firebase.google.com/project/vesper-21ef9/firestore).

- Если база уже есть, используй существующую: удалять или пересоздавать её не нужно.
- Если базы ещё нет, нажми **Create database / Создать базу данных**, выбери стандартную базу **`(default)`**, редакцию **Standard**, если этот выбор предлагается, и режим **Production / Рабочий режим**. Выбери подходящий регион; после создания его нельзя изменить.
- Останься на Spark. Серверные Cloud Functions для этой синхронизации не требуются.

Затем открой вкладку **Rules / Правила**, полностью вставь содержимое [firestore.rules](../firestore.rules) из этой же ветки и нажми **Publish / Опубликовать**. Нужны именно опубликованные правила, одного сохранения текста недостаточно.

Коллекции вручную создавать не нужно. После создания профиля приложение запишет данные в `users/{uid}/records`. Чужие профили, дневник цикла и служебные коллекции закрыты правилами. Физическое удаление документов запрещено; приложение передаёт отметку удаления для синхронизации.

Для владельца, использующего Firebase CLI, подготовлены `.firebaserc` с проектом `vesper-21ef9` и `firebase.json`. Публикация только правил — `npx firebase deploy --only firestore:rules --project vesper-21ef9` после собственного входа в CLI. Для настройки через Console выполнять эту команду не нужно.

## 4. Действия в Vercel

1. Открой существующий проект **vesper**. Код находится в ветке **`codex/vesper-v7-planner`**, [изменения №1](https://github.com/laworu/vesper/pull/1). Preview этой ветки: [открыть VESPER](https://vesper-git-codex-vesper-v7-planner-laworu.vercel.app/).
2. Для **Authentication и Firestore переменные окружения добавлять не нужно**: публичная конфигурация уже в проекте. Приватный ключ сервисного аккаунта для этих двух функций не нужен.
3. Если в **Settings → Environment Variables** уже есть `FIREBASE_WEB_CONFIG`, удали ненужное переопределение или проверь, что там корректный JSON именно `vesper-21ef9`. После изменения переменных сделай **Redeploy** и проверь нужное окружение: **Preview** или **Production**.
4. В **Deployments** дождись статуса **Ready** у последней сборки этой ветки. При обычном Git-подключении сборка запускается после обновления ветки.
5. После проверки Preview объедини [изменения №1](https://github.com/laworu/vesper/pull/1) с `main`, чтобы обновился основной адрес `vesper-xi-flame.vercel.app`. До объединения основной сайт продолжает показывать прежнюю версию.

ИИ Кайро и уведомления при закрытом сайте остаются отдельными интеграциями: для них нужны дополнительные серверные настройки из [README](../README.md). Ключи от этих служб добавляй непосредственно в Vercel; не публикуй их в GitHub и не отправляй в чат. Web config Firebase из инструкции является публичным и приватным ключом не считается.

## 5. Проверить телефон и компьютер

1. На компьютере открой Preview, создай аккаунт VESPER по почте и паролю, открой ссылку подтверждения в письме. Вернись в VESPER и нажми кнопку проверки подтверждения. Если письмо не пришло, проверь спам или запроси повторное.
2. Создай профиль, цель и задачу к ней. Дождись статуса **«Профиль синхронизирован»**.
3. На телефоне открой тот же Preview и войди **в тот же аккаунт**. Цель и задача должны появиться. Заверши задачу на телефоне и проверь изменение на компьютере.
4. Перезагрузи страницу. Затем временно отключи сеть, измени задачу и верни подключение: локальные изменения должны дождаться отправки. Удаление/отмена выполнения тоже должно отразиться на втором устройстве.
5. Выйди и войди под другим подтверждённым аккаунтом: записи первого не должны появиться. У каждого нового профиля своё начальное состояние.

Если видишь ошибку доступа к базе, проверь публикацию правил, создание базы `(default)` и подтверждение почты, затем нажми **«Попробовать снова»**. Если Firebase сообщает, что способ входа не включён, вернись к шагу 1. При `unauthorized-domain` проверь шаг 2. Квоты Spark можно смотреть в Firebase Console; платный тариф автоматически не включается.

## Что проверяется автоматически

`npm run test:firebase` запускает локальные эмуляторы с виртуальным именем `demo-vesper-sync`. Проверяются права владельца, изоляция аккаунтов, запрет гостям и неподтверждённым адресам, формат документов, отметки удаления, защита дневника, правила напоминаний, подтверждение почты и обмен двух независимых Firebase-клиентов. Настоящий проект `vesper-21ef9` эти проверки не изменяют.
